No. 05
The deliverable

Five rules for arguing with it.

[One line: none of them need a new tool, only a different instruction.]

01

Argue, don't agree.

Do not ask "does this work". Say "argue against this" instead. An assistant defaults to agreeing with whatever you put in front of it, so you have to ask it not to.

02

Name your assumptions.

Get it to list what the plan depends on before it argues the case. A weak assumption named early is cheap to fix and expensive to find later.

03

Let it ask back.

Read what it says it was not told, not only what it disagrees with. A gap in your own brief is a second finding, not a failure of the plan.

04

Argue before it ships.

Run it on the plan, the quote or the email before a client sees it, not after. The argument is worth nothing once the thing is already out the door.

05

Fix it. Don't defend it.

Change what it finds instead of arguing back at it. The point of the exercise is a better plan, not a plan you talked it out of doubting.

Arguing is useful.]

Prompt to steal

Redline your own plan.

This is the card from the Prompt Shelf. Paste your plan or draft where the prompt below expects it.

Prompt / Redline your own plan 
Before I act on this, take the other side.

Argue against it. Tell me where the logic is weakest, what I have assumed
without checking, and what could go wrong that I have not accounted for.

Then tell me the things I need to know about this that I have not asked you.
Tip. Do not defend the plan back to it. Fix what it finds instead of arguing your case.
Use it like this
01

Get the plan or draft on screen, straight after it lands in the same chat.

02

Paste this prompt as your next message.

03

Read the assumptions and the missing questions before you read the argument itself.

Best for

Any plan or draft before it reaches a client: a proposal, a price change, a build plan, a schedule.

Not ideal for

A plan already checked by someone else, or a fact it cannot verify itself. It argues from logic, not evidence.

Make it automatic

Ask. Argue. Fix.

Three habits. One is a prompt, two are discipline.

01

Keep the argument one paste away

Save this prompt where you keep the others. Run it on the next plan before it goes anywhere.

Set once
02

Ask it to argue first

Before you act on anything it gives you, add "take the other side" to the same chat. Every task, not just the big ones.

Every task
03

Fix what it finds

Read the weak points and the missing questions before anything else. If nothing about the plan changes, you did not really argue.

Every time

Run it yourself

Five exercises. Two minutes to ten.

[One line: do not take my word for it, run it on your own plan.]

01

Argue with the last plan

  1. Find the last plan or draft it gave you today.
  2. Paste it back in and run the page 05 prompt.
  3. Read what it assumed before you read the argument.
What you learn. Something in there was assumed, not checked. Do this one first.
02

Check, then argue

  1. Ask "does this work" the way you normally would.
  2. New chat. Paste the same plan, run the prompt instead.
  3. Compare the two answers.
What you learn. The second answer finds something the first one missed.
03

Argue with your own draft

  1. Paste an email or a quote you are about to send.
  2. Run the prompt on it.
  3. Read what it flags before you hit send.
What you learn. It catches the gap you would otherwise have found out about from the client.
04

Argue both sides

  1. Run the prompt on a real plan.
  2. Same chat, ask it to argue for the plan instead.
  3. Compare the two arguments.
What you learn. It argues either side equally well, which is why you have to ask for the argument you need.
05

Put it at the top

  1. Save the prompt where you keep your others, today.
  2. Run it on the next plan before you act on it.
  3. Fix one thing it found.
What you learn. A plan with the holes found first is worth more than one with holes nobody has looked for yet.
