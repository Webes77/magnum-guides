This week

Why the answers go generic.

In nearly every Foundations session someone says the same thing. It keeps giving me generic answers.

Then I watch them work. They open a fresh chat and type out who they are, what they sell, what came in overnight and who they are seeing at ten. Every morning. Or they type none of it and expect the model to already know.

Neither of those is a prompting problem. That is why the prompting advice never fixed it.

The fix is a sorting job. Every piece of context you give an AI is one of two kinds. One kind you write down once. The other kind you connect to. Most people have the two backwards.

This Field Note gives you the sorting question, a prompt that runs the sort for you, and five exercises to do in Claude or ChatGPT this week so you see it for yourself rather than take my word for it.

Ten minutes to learn. One afternoon to fix.

Two kinds of context

One you write down. One you connect to.

Context is not one thing. Sort it before you store it.

Frozen knowledge

Anything that rarely changes. Who the business is, who it sells to, house tone, how output should be formatted, standing rules.

Set it once. Edit it only when the situation changes.

Custom instructions
Project instructions
Uploaded reference docs
Living context

The current state. Who you are pitching today. What came in overnight. What the pipeline looks like this morning.

It is not a document. It is a connection to a source of truth that keeps changing.

Calendar
Inbox
CRM, web search, connectors
The
trap

Automatic memory. Claude and ChatGPT both keep one. It updates itself, so it feels live, and people file it as current state. It is not.

Memory stores slow facts. Prefers bullet points. Works in marketing. That is frozen knowledge the model keeps on your behalf. Nobody wrote it, so nobody reviews it, and it goes stale without anyone noticing.

the model keeps for you.

The deliverable

One question sorts all of it.

Ask it about every piece of information you give an AI. How often does this change?

01

Rarely? Write it once.

Put it in custom instructions, Project instructions or a reference doc. Edit it only when the fact changes.

02

Weekly or daily? Connect it.

Link the calendar, inbox, CRM or web search. Never retype what a connector can read.

03

Never type living context by hand.

If you are pasting this morning’s state into the chat, the setup is wrong. The prompt is fine.

04

Never expect it to already know.

The model does not know who you are seeing at ten. It knows what is written down or connected.

05

Treat memory as frozen.

Review it on a date. Delete what has gone stale. It will not fix itself.

Rarely means write it down once.
Daily means connect it. That is the whole diagnostic.

Prompt to steal

Run the sort on your own setup.

Best for custom instructions, Project instructions, memory entries, and anything you find yourself pasting in more than once.

Prompt / Context audit 
Audit the context below for an AI assistant setup.

For every fact, claim or instruction, answer one question: how often does this change?

Sort each item into one of three lists:
1. Rarely (frozen knowledge). Keep it here.
2. Weekly or daily (living context). Move it out. Name the live source it should be connected to instead: calendar, inbox, CRM, web search or another source of truth.
3. Unclear. Ask me.

Then flag anything that is already out of date or contradicts another item.

Keep the wording of each item exactly as I wrote it. Do not rewrite my instructions. Only sort them.

CONTEXT:
[paste custom instructions, Project instructions or memory entries here]
Tip. Run it on your memory entries first. That list is usually the worst.
Use it like this
01

Open your custom instructions or Project instructions. Copy the lot.

02

Paste them under the prompt in a fresh chat.

03

Move list 2 out and connect it. Delete anything flagged stale.

Best for

Settings, Project instructions, memory, and any document you keep uploading.

Not ideal for

A single chat where you are working something out. That context is meant to be temporary.

Make it automatic

Set it once. Connect the rest.

Three places. Each one holds one kind of context. Once they are set, you stop typing.

01

Instructions and Projects

Hold the frozen knowledge. Who you are, who you sell to, tone, format, standing rules.

Set once. Edited when the facts change
02

Connectors

Hold the living context. Calendar, inbox, CRM, documents, web search. The model reads the state instead of being told it.

Connected once. Always current
03

Memory

Holds whatever the model decided to keep. Treat it as frozen. Put a review date in the calendar.

Audited every quarter, minimum
Frozen gets written.
Living gets connected.
Two buckets. Everything you give an AI goes in one of them.

Build side

Three lines that end the compliance conversation.

The companies actually running AI agents in production share three habits. They are also a scoping rule. Put them in every rollout plan.

01

Narrow scope

One agent, one job. Not an end-to-end workflow. If it does five things, it is five agents.

Scope
02

Written trail

Every decision and action the agent takes is logged in writing. Nothing happens that cannot be read back later.

Log
03

Human gate

A person reviews before anything high-stakes executes. Sending, paying, deleting, committing.

Gate
Narrow scope. Written trail.
Human gate.
Three lines. They cost nothing, and they answer the nervous question before it is asked.

Run it yourself

Five exercises. Ten minutes each.

Do not take my word for it. Each one shows you the difference on your own screen.

01

Audit your memory

  1. Open Settings. Read every memory entry the model holds on you.
  2. Mark each entry as still true or stale.
  3. Delete the stale ones.
What you learn. The count of stale entries is your rot rate.
02

Run the sort

  1. Copy your custom instructions or Project instructions.
  2. Paste them under the page 05 prompt in a fresh chat.
  3. Move every weekly or daily item out.
What you learn. Anything that came back weekly was living context filed as frozen.
03

Ask a living question two ways

  1. With the calendar disconnected, ask: what is on my calendar tomorrow?
  2. Connect the calendar.
  3. Ask the same question again.
What you learn. The first answer is a guess. The second is state. Do this one first.
04

Watch memory freeze something

  1. Tell the model: I am pitching [client] this week.
  2. Next week, in a new chat, ask: who am I pitching this week?
What you learn. It still says [client]. Living context stored as frozen, in front of you.
05

Scope one automation against the three lines

  1. Pick one automation you already run.
  2. Write one line each: its single job, where its log is, where the human gate is.
  3. If any line is blank, the automation fails the rule.
What you learn. The three lines become a checklist you have already passed or failed.
