# Roadmap: from folder of files to a real members area

You don't have to build the whole thing at once. Each stage below stands on its
own and is genuinely useful, so you can stop at any point and still have something
that works.

## Stage 1. Everything in one place  ✅ (you're here)

All guides and resources live in this repo, organised into folders, with a home
page (`index.html`) that links to them. This is your single source of truth.

**What's left for you:** drag your desktop files into the synced folder (via
GitHub Desktop) and drop them into `clients/`, `notes/`, etc.

## Stage 2. A live website (free)

Turn on **GitHub Pages** (Settings → Pages → deploy from `main`). Your `index.html`
becomes a real site at `https://webes77.github.io/magnum-guides/`. Share the link,
bookmark it on your phone, send it to clients. Still no logins. Anyone with the
link can view.

## Stage 3. A proper front door

Add a custom domain (e.g. `members.magnumai.com.au`), a logo, and navigation so it
feels like a product, not a folder. Still hosted free on GitHub Pages.

## Stage 4. Actual "members only" (logins)

This is where a plain static site isn't enough. Real logins need a platform that
handles accounts and payments. When you get here, the usual options are:

- **Memberstack / Outseta / Podia.** Bolt logins onto your existing pages.
- **A membership platform** (Kajabi, Circle, Teachable). More turnkey, less custom.
- **A custom build.** Most flexible, most work.

The good news: because your content is already organised and version-controlled
here, moving it into any of these later is straightforward. Nothing you do now is
wasted.

## A note on scale

GitHub is perfect for Stages 1–3. Stage 4 (real memberships/payments) is a
separate decision. When you're ready, that's a good moment to plan the platform
choice properly rather than rush it.
